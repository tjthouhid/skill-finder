# Skill Finder — design spec

Date: 2026-11-02

## Purpose

Given a plain-language need ("I want human-feeling web design", "shoppers abandon checkout"), tell the user which installed agent skills fit, which guided journey fits if the ask is a whole project, how to install anything missing, and give a ready-to-paste prompt that invokes the chosen skills.

Users: the owner (tjthouhid) working in Claude Code and Codex CLI on this Mac; later, anyone who installs the skill from GitHub.

Success: in either tool, `/skill-finder <need>` (or a natural "which skill should I use for…") returns 2–4 ranked skills with a one-line reason each, an optional journey, install lines only for skills not installed in the current tool, and one prompt. Answer arrives from one script run, not from loading the whole catalogue into context.

## Decisions (agreed)

- Coverage: every skill installed on this machine (Claude Code skill dirs, Codex skill dir, Claude plugin caches), enriched with the Wondel field guide's categories, "use when" lines, 14 journeys and 8 example routes. Re-runnable index.
- ChatGPT side = Codex CLI. Same SKILL.md and scripts; no Custom GPT package.
- Form factor: a single skill `skill-finder` (not a plugin). Trigger phrase and `/skill-finder`.
- Matching: stdlib Python keyword ranker (`find.py`) returns top candidates; the agent reasons over those. No embeddings, no third-party deps.

## Data

### `wondel.json` (curated)

Source: the field guide HTML (`categories`, `journeys`, `journeySteps`, example routes) plus the Wondel catalogue slugs.

```json
{
  "install": "npx skills add wondelai/skills --skill {slug}",
  "install_all": "npx skills add wondelai/skills --all --global",
  "categories": ["Design & UX", "Marketing & Messaging", "..."],
  "skills": [
    {
      "name": "StoryBrand Messaging",
      "guide_slug": "storybrand",
      "slug": "storybrand-messaging",
      "category": "Marketing & Messaging",
      "summary": "Explain a product clearly by framing the customer as the main character...",
      "use_when": "Use when the homepage talks about the company but visitors don't understand the benefit.",
      "aliases": ["storybrand", "story brand"]
    }
  ],
  "journeys": [
    {
      "slug": "create-website",
      "name": "Create a Website",
      "tagline": "Blank page → clear, designed, conversion-focused website",
      "phases": 10,
      "skills": ["one-page-marketing", "storybrand-messaging", "..."],
      "fits": "new marketing site or landing page from scratch"
    }
  ],
  "routes": [
    {
      "name": "Improve an online shop with abandoned checkout",
      "steps": [["cro-methodology", "locate the drop-off"], ["ux-heuristics", "remove checkout friction"]],
      "shortcut": "improve-website",
      "note": "use conversion-optimization for one funnel"
    }
  ]
}
```

`slug` is the installed directory name (the thing `Skill` / `npx skills add --skill` uses). `guide_slug` is what the guide printed; kept for matching and the catalogue link. Known mismatches to encode: storybrand→storybrand-messaging, the-mom-test→mom-test, refactoring→refactoring-patterns, software-design→software-design-philosophy, legacy-code→working-with-legacy-code, design-of-everyday-things→design-everyday-things, 100m-offers→hundred-million-offers, 1-page-marketing-plan→one-page-marketing, inspired→inspired-product. Journey skill lists come from each journey's installed SKILL.md description (they enumerate their phases); the guide's `journeySteps` are the fallback.

### `skills.json` (generated)

One record per installed skill, keyed by slug:

```json
{
  "generated_at": "2026-11-02T...",
  "roots": {"claude": ["~/.claude/skills", "~/.claude/plugins/cache/**/skills"], "codex": ["~/.codex/skills"]},
  "skills": {
    "refactoring-ui": {
      "name": "refactoring-ui",
      "display_name": "Refactoring UI",
      "description": "<SKILL.md frontmatter description>",
      "summary": "<wondel summary or first sentence of description>",
      "use_when": "<wondel use_when or null>",
      "category": "Design & UX",
      "source": "wondel" | "gstack" | "superpowers" | "aws-startup-advisor" | "anthropic" | "unknown",
      "author": "<frontmatter metadata.author or null>",
      "install": "npx skills add wondelai/skills --skill refactoring-ui" | null,
      "installed": {"claude": true, "codex": false},
      "paths": {"claude": "/Users/.../refactoring-ui/SKILL.md"},
      "journeys": ["create-website", "improve-website"],
      "aliases": []
    }
  },
  "journeys": [...copied from wondel.json, with skills resolved...],
  "routes": [...]
}
```

Source detection: `wondel` if slug is in wondel.json; `metadata.author` from frontmatter when present; plugin name when the SKILL.md lives under `~/.claude/plugins/cache/<marketplace>/<plugin>/`; gstack when the frontmatter description ends with `(gstack)` or the dir sits in a gstack install; else `unknown`. Install line only for `wondel` (per-skill) and for plugins (`/plugin install <plugin>@<marketplace>`); others `null`.

Skills with no `SKILL.md` (e.g. `synced/`) are skipped. Name conflicts between roots: first root wins, both paths recorded.

## Scripts

Both: Python 3.9+, stdlib only, run with `python3 -I`, paths passed as arguments or env, exit non-zero with a one-line error on failure.

### `build_index.py`

```
python3 -I scripts/build_index.py [--data DIR] [--claude-root PATH ...] [--codex-root PATH ...] [--quiet]
```

1. Walk each root for `*/SKILL.md` (depth-limited; plugin caches: `**/skills/*/SKILL.md`).
2. Parse YAML frontmatter with a small hand-rolled parser (keys: name, description, license, metadata.author, metadata.version). Multi-line and quoted descriptions supported; anything unparseable → description = first non-frontmatter paragraph.
3. Merge with `wondel.json` by slug or alias.
4. Write `data/skills.json`. Print counts: total, per source, Wondel skills in guide but not installed.

### `find.py`

```
python3 -I scripts/find.py "query text" [--tool claude|codex] [--top N=8] [--json]
```

1. Load `skills.json`.
2. Tokenize query (lowercase, strip punctuation, drop stopwords, naive stemming: strip trailing s/ing/ed). Expand a small synonym table (`web design`→ui, frontend, landing, visual; `checkout`→conversion, funnel; `slow`→performance; `legacy`→untested, old code; `human`→taste, handcrafted, anti-slop; etc.) kept in the script.
3. Score each skill: weighted term hits across name (×4), aliases (×4), use_when (×3), category (×2), summary (×2), description (×1), with document-length normalization. Phrase match bonus for bigrams.
4. Score journeys the same way over name + tagline + fits + member skill names.
5. Output (default: Markdown for the agent to read):

```
## Skills
1. refactoring-ui  [installed: claude ✓ codex ✗]  score 9.1  (Design & UX, wondel)
   Make interfaces look consistent and intentional...
   Use when: the UI works but looks uneven, cluttered, or "generated."
   Install (codex): npx skills add wondelai/skills --skill refactoring-ui -a codex
...
## Journeys
1. create-website — Blank page → ... (10 phases) [installed ✓]
## Routes that mention these
- Build a small local service website → one-page-marketing → storybrand-messaging → refactoring-ui ...
```

`--tool` defaults to `claude`; the SKILL.md tells the agent to pass `codex` when running under Codex. `--json` emits the same as structured data.

## SKILL.md behaviour

Frontmatter: `name: skill-finder`, description with triggers ("which skill should I use", "what skill for", "is there a skill for", "find me a skill", "/skill-finder"), author tjthouhid.

Body instructs the agent:

1. Decide tool: `codex` if running under Codex CLI, else `claude`.
2. Run `find.py` with the user's need verbatim (plus the project's language/stack if the user gave it). If `skills.json` is missing or older than 30 days, run `build_index.py` first.
3. Read the top results. Pick 2–4 skills that actually fit; drop near-duplicates (prefer the installed one; prefer the Wondel one when a gstack/other overlaps and the ask is advice-shaped). If the ask is a whole project ("build me a…", "my site is failing"), lead with the matching journey and list its skills under it.
4. Reply format (short, no preamble):
   - **Best fit** — slug, one line why, installed/not.
   - **Also consider** — up to 2 more.
   - **Journey** — if applicable.
   - **Install** — only lines for missing skills in the current tool; `skills add` for Wondel, `/plugin install` for plugins, nothing for unknown-source (say "already installed").
   - **Try this** — one ready prompt: `Use <slug> [and <slug>] to <user's goal in their words>. Start with the smallest first step.`
5. If nothing scores above a floor, say so and suggest the closest category, or `build_index.py` if the index looks stale.
6. Never invent install commands or skills not in the index.

## Install / distribution

- Local now: symlink `skill-finder/` into `~/.claude/skills/skill-finder` and `~/.codex/skills/skill-finder`.
- Public: push repo to GitHub as `tjthouhid/skill-finder`; README shows `npx skills add tjthouhid/skill-finder` and `npx skills add tjthouhid/skill-finder -a codex`. First-run on a fresh machine: SKILL.md step 2 regenerates `skills.json` for that machine.

## Error handling

- Missing `skills.json` → find.py prints one line telling the agent to run build_index.py (exit 2).
- Unreadable SKILL.md → skipped, counted in build summary.
- Empty/garbage query → find.py prints usage (exit 1).
- Roots that don't exist → silently skipped; recorded as absent in `roots`.

## Testing

`tests/test_find.py` (unittest, run with `python3 -I -m unittest`):

- Build an index from `tests/fixtures/skills/` (a dozen minimal SKILL.md files mirroring real slugs) plus the real `wondel.json`; assert slug mapping, source detection, installed flags for a fake codex root.
- Query fixtures, asserting expected slug in top 3:
  - "human type web design, not generic" → `refactoring-ui` or `design-taste-frontend`
  - "shoppers leave at checkout" → `cro-methodology`
  - "old untested code I'm scared to change" → `working-with-legacy-code`
  - "app depends on third party APIs, before launch" → `release-it`
  - "build a landing page from scratch" → journey `create-website`
  - "customers don't understand what we do" → `obviously-awesome` or `storybrand-messaging`
- Frontmatter parser: quoted single-line, multi-line `>`-folded, unquoted with colons.
- Live check (manual, this session): run the real index and the six queries above in Claude Code.

## Out of scope

Embeddings, a web UI, a Custom GPT, auto-installing skills, tracking usage, editing other skills.
